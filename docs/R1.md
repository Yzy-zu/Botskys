# R1 · contrato determinista

Lexer incremental con spans originales; registro único de 152 rutas y tres alias
(`/descargar`, `/conv`, `/web`); argumentos declarados como str/int/float/bool/tuplas
inmutables. Cada campo define tipo, rango, longitud, presencia, default, opción y
correspondencia original. El router conserva una serialización canónica versionada.

La ayuda y los errores se derivan del mismo registro. `/ayuda` lista las familias;
`/ayuda dl` detalla usos y los comandos con archivos explican adjunto/cita exacta.
El parser solo recibe texto: no concede autoridad, no abre DB/archivos, no importa
Zhana y no llama redes, IA ni handlers. Su salida no se vuelve a interpretar como
lenguaje natural. Las respuestas de IA y documentos se tratarán como contenido.

Campos finales conservan bytes de texto (incluidos comillas, barras, saltos y
opciones aparentes) después del espacio sintáctico. Comillas se decodifican solo
en campos múltiples. `--` fuerza el inicio literal; `/voz -- crear poema` lee el
texto y `/voz crear poema` pide composición. No existe evaluación de shell.

Conciliación original por acción y campo: command-matrix.csv. Los campos internos
como attachment_id, time_text, interpretation y recibos no se solicitan al usuario.
Las identidades/objetivos públicos son referencias verificables que el backend
resolverá; un nombre o ID escrito no acredita permiso ni existencia del objetivo.

Decisiones técnicas/adaptaciones sin recortar capacidad:

- /cancelar ID centraliza cancelación exacta. ask/silent/table/footer/text_lines de
  conversación son presentación de Result, no acciones desde contenido generado.
- `botsky` nombra el perfil de voz antes llamado `zhana`; conserva las otras doce
  voces. No se traslada su personalidad. Blackjack conserva 20–1000 XP y ruleta
  1–1000; el backend deberá validar otra vez saldos y reglas.
- La creación de partida/sala emite ID propio. Un ID no permite sobrescribir otra.
  Blackjack sin ID se resuelve solo si hay partida propia inequívoca y vigente.
- Pack agrega filtro de categoría en catálogo según el plan (el validador previo
  solo admitía página). /pack confirmar ID conserva el flujo de compra previa.
- /hh estado|parar|lluvia|airdrop [ID] permite evento exacto; reclamar exige ID real.
- /clip poner ID o --nombre TEXTO; /clip ajustar subir|bajar VALOR conserva ajuste
  relativo; /avatar permite --duracion salvo fondo; agenda conserva audio preparado,
  volumen, Live y fin tras audio. IDs de clip/audio son nuevos IDs de Botsky.
- /buscar --terminos "uno,dos" CONSULTA conserva hasta ocho términos explícitos;
  query mantiene site: literalmente. No atribuir relevancia antes de ver resultados.
- Fecha/hora válida en sintaxis no garantiza que sea futura: corte, horizonte y
  ambigüedad de zona se validarán con el reloj y los permisos del dominio.
- ID de vista de descarga/Drive es explícito; su selección deberá acreditar dueño,
  chat, época, entrega y vigencia. No se interpreta un número aislado.

Comprobación: tests/test_commands.py (casos contractuales y todos los ejemplos de
registro con I/O prohibido). El primer recorrido encontró hora 24:00 aceptada por
time.fromisoformat del host: se exige construcción horaria 00:00–23:59. También
se corrigió un offset esperado de prueba; los spans conservaban el origen real.

Estos resultados cierran sintaxis y contrato, no motores ni negocios. La matriz
mantiene aceptación de herramienta NOT_TESTED hasta el bloque correspondiente.
R2 es el primer consumidor durable y debe revalidar ámbito antes de efectos.
